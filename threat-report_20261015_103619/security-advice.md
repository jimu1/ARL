# 安全建议（邮箱注册功能）

1. **注册流程逐步校验、验证凭证与邮箱强绑定**：落库创建账号时必须二次校验"邮箱+验证码"的验证结果，禁止跳过任一步骤；验证凭证由服务端保存绑定关系、一次性使用、成功后立即失效。禁止"用 A 邮箱的验证码注册 B 邮箱"，防止邮箱归属伪造与账号接管。

2. **口令使用强哈希 + 每用户独立盐**：不得沿用现有 `gen_md5(salt+password)` 的 MD5+全局固定盐方案，改用 bcrypt / Argon2id / PBKDF2，禁止 MD5/SHA1/单轮 SHA256；口令不得明文出现在数据库、日志或响应包中。

3. **邮箱验证码安全策略**：验证码 ≥6 位（或高熵随机 Token），同邮箱错误 3 次即失效，有效期 ≤5 分钟，验证成功一次后立即失效，且不在响应包中回显。

4. **注册与发码接口防滥用**：单邮箱 60 秒内限发 1 次、单日设上限；发码与注册接口按 IP/设备限流并前置滑块或图形验证码；发码接口做幂等/重放保护。同时对"邮箱是否已注册"保持一致的响应文案、状态码与响应时间，避免账号枚举。

5. **传输安全与接口边界**：注册相关接口强制 HTTPS（TLS 1.2+，禁用 TLS 1.0/1.1 与 SSLv2/v3）；服务端固定创建为普通用户角色，不信任前端传入的角色/权限字段，仅经受控服务写入 `user` 集合。邮箱按敏感数据处理，脱敏展示，日志与异常堆栈不得出现邮箱、验证码明文；并记录注册成功、验证失败、限流拦截等安全日志。
