# 用户管理模块（含注册）安全需求报告

> 分析时间：2026-10-14
> 知识库来源：顺丰 SecGuard 威胁知识库（身份认证 / 验证码 / 权限管理 / 敏感数据 / 安全日志 / 业务安全）
> 分析对象：用户管理功能模块，支持用户注册

---

## 一、功能概述

用户管理模块提供账号全生命周期管理能力，本期范围包含：

| 子功能 | 说明 |
|-------|------|
| 用户注册 | 手机号/邮箱 + 密码注册，含验证码校验 |
| 账号存储 | 用户基础信息（手机号、邮箱、密码等）持久化 |
| 账号查询 | 查询用户信息 / 列表 |
| 账号修改 | 修改用户资料、重置密码 |
| 账号禁用 | 启用 / 禁用账号 |

涉及安全域：**身份认证、验证码、权限管理、敏感数据、安全日志、业务安全（接口）**

---

## 二、识别的威胁及风险等级

### 🔴 高危威胁

| 编号 | 威胁 | 攻击路径 | 风险说明 |
|-----|------|---------|---------|
| H1 | 未授权访问 | 用户管理接口（查询/修改/禁用）未做后端鉴权，攻击者直接构造请求操作账号 | 可批量增删改账号，数据被篡改/泄露 |
| H2 | 水平越权 | 个人资料查询/修改接口篡改 userId，操作他人账号 | 可查看/修改他人账号信息 |
| H3 | 垂直越权 | 普通用户改 URL 或参数调用管理员接口 | 低权限用户获取管理权限 |
| H4 | 敏感数据明文存储 | 手机号、邮箱、身份证等 C4 数据未加密存储 | 一旦 SQL 注入/拖库，明文直接泄露 |
| H5 | 敏感数据明文展示 | 用户列表/详情接口返回手机号、邮箱明文（前端伪脱敏无效） | 接口级泄露，非必要展示明文 |

### 🟡 中危威胁

| 编号 | 威胁 | 攻击路径 | 风险说明 |
|-----|------|---------|---------|
| M1 | 短信验证码可爆破 | 注册验证码为 4 位纯数字或未限制验证次数 | 爆破验证码绕过注册验证 |
| M2 | 验证码回显 | 注册验证码在响应包中返回 | 攻击者直接读取验证码 |
| M3 | 短信轰炸 | 发送验证码接口无前置图形/滑块校验，可重放 | 骚扰用户、消耗短信费用 |
| M4 | 短信模板注入 | username 等用户输入被拼入短信模板 | 借平台发送钓鱼/违规内容 |
| M5 | 密码策略不足 | 注册密码长度/复杂度不足 | 账户易被暴力破解 |
| M6 | 接口未鉴权/无防护 | 注册、查重接口缺少必要鉴权或频率限制 | 账号枚举、接口滥用 |
| M7 | 密码重置流程漏洞 | 重置接口未二次校验、重置链接可预测 | 任意重置他人密码 |

### 🟢 低危威胁

| 编号 | 威胁 | 风险说明 |
|-----|------|---------|
| L1 | 敏感数据操作日志缺失 | 账号查看/修改/删除无埋点日志，无法审计溯源 |
| L2 | 错误信息过详细 | "该手机号已注册"可用于账号枚举 |
| L3 | 传输协议不安全 | 未强制 HTTPS / TLS 1.2+ |

## 三、安全需求清单（按优先级）

### 🔴 高危需求（必须实现，阻断发布）

1. **接口鉴权**：用户管理模块所有接口（查询/修改/禁用）必须做后端身份认证，敏感数据操作（增删改查）必须做严格权限校验，禁止仅前端限制。
2. **水平越权防护**：查询/修改个人资料必须基于服务端会话（Session/Token）中的用户身份，禁止信任客户端传入的 userId；校验目标资源是否属于当前用户。
3. **垂直越权防护**：管理类接口基于角色（RBAC）在后端校验权限，低权限用户访问高权限功能一律拒绝；内部员工系统建议接入百源做角色权限控制。
4. **敏感数据加密存储**：手机号、邮箱、身份证、银行卡等 C4 数据统一使用加密机加密存储，禁止使用其他加密算法。
5. **敏感数据脱敏展示**：接口不返回明文，遵循"非必要不展示明文"；手机号脱敏为前 3 后 4（138****2343）、邮箱保留首位和 @ 后（w*******@qq.com）；禁止前端伪脱敏。

### 🟡 中危需求（建议实现）

6. **短信验证码复杂度**：验证码位数 ≥ 6 位，禁止 4 位纯数字。
7. **验证码防爆破**：同一验证码验证错误 3 次即失效；正确验证一次后立即失效。
8. **验证码有效期**：有效期 ≤ 5 分钟（Redis 设置 TTL）。
9. **验证码不回显**：验证码仅后端生成与校验，不在响应包中返回，前端不参与校验逻辑。
10. **短信轰炸防护**：发送验证码前增加图形验证码/滑块验证；对同一手机号/IP 做频率限制（如 60 秒 1 次、每日上限）。
11. **禁止动态短信模板**：用户输入的字符串（如 username）禁止拼入短信内容，使用固定模板。
12. **密码安全策略**：ToC/内部系统密码长度 ≥ 10 位，ToB ≥ 8 位；复杂度 ≥ 3 种（大小写、字母、数字、特殊符号）；禁止连续 4 位顺序/逆序数字、字母、重复字符。
13. **密码找回流程**：每一步验证结果与后续步骤关联；重置链接随机生成（12 位大小写字母+数字+特殊符号），有效期 ≤ 5 分钟；手机号与验证码做二次匹配校验。
14. **接口防护**：对外接口强制 HTTPS（TLS 1.2+），禁用 SSLv2/v3、TLS 1.0/1.1；接口仅返回完成操作所必需的最少数据。

### 🟢 低危需求（酌情实现）

15. **安全日志**：记录账号查看/修改/删除操作埋点日志，字段含 operateUserid、operateFunction、operateType、sensitiveDataType、sensitiveDataContext、sensitiveDataCount。
16. **错误信息收敛**：注册/查询失败返回统一模糊提示，避免账号枚举。
17. **传输加密**：全站强制 HTTPS，接口不从 URL、错误消息中暴露敏感信息。

## 四、检查清单

### 注册接口

- [ ] 注册接口是否需要并实现了频率限制/防刷？
- [ ] 短信验证码位数是否 ≥ 6 位？
- [ ] 验证码有效期是否 ≤ 5 分钟？
- [ ] 验证码错误 3 次是否失效？正确验证后是否立即失效？
- [ ] 验证码是否不在响应包中回显？
- [ ] 发送验证码前是否有图形/滑块验证防轰炸？
- [ ] 短信模板是否为固定模板（无用户输入拼接）？
- [ ] 注册密码长度/复杂度是否符合策略？是否校验连续/重复字符？
- [ ] 注册返回信息是否避免账号枚举？

### 用户管理接口

- [ ] 所有接口是否做了后端身份认证？
- [ ] 查询/修改个人资料是否基于服务端会话身份，而非客户端 userId？
- [ ] 管理类接口是否基于角色在后端做权限校验？
- [ ] 是否存在无需登录即可访问的账号接口？
- [ ] 敏感数据操作是否做严格权限验证？

### 敏感数据

- [ ] 手机号、邮箱、身份证等是否用加密机加密存储？
- [ ] 接口是否返回明文（是否存在前端伪脱敏）？
- [ ] 展示是否符合脱敏规则（手机号前 3 后 4、邮箱保留首位和 @ 后）？
- [ ] 是否禁止批量明文展示？
- [ ] 是否禁止对用户提供 Web 解密接口？

### 日志与传输

- [ ] 账号查看/修改/删除是否记录埋点日志（含操作人、操作类型、数据类型、上下文、数量）？
- [ ] 是否全站强制 HTTPS 且使用 TLS 1.2+？
- [ ] 错误消息、URL 是否避免暴露敏感信息？
